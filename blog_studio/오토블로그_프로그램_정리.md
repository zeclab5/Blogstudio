# 블로그 스튜디오 — 오토블로그 발행 프로그램 정리

> 한/영 블로그를 **AI로 글을 쓰고, 사진을 넣고, 정해진 시각에 자동으로 발행**하는 프로그램.
> 여러 블로그(다른 구글 계정 포함)를 한 프로그램에서 관리합니다.
> 위치: `C:\blogger\blog_studio\` · 실행: `블로그스튜디오.bat`

## 2. 핵심 기능

### 🎬 시리즈 기획 (첫 탭)
- 한국을 찾는 외국인이 **관심 갖는 키워드를 카테고리별로 조사**(1~10위)해서 고르고,
- 그 키워드로 **연결성 있는 5편+ 시리즈**(제목·후킹·요약)를 AI가 기획 → 캘린더에 자동 배정.
- **카테고리는 블로그마다 다름** — [📅 요일별 발행]의 **주제에서 자동으로 채워집니다**(활성 요일의 주제). 즉 블로그를 전환하면 그 블로그의 요일 주제가 카테고리로 보입니다.
  - **새 주제 추가**: 카테고리 칸에 입력 후 **[+ 추가]** → 그 블로그에 영구 저장(`series_categories`). 직접 타이핑해 즉석 사용도 가능(편집형 콤보박스).
  - 요일 주제가 하나도 없으면 기본 카테고리(Traditional Arts / Performances / Regional Culture / Korea 101 / Travel)로 폴백.
- **기획 요청사항(직접 입력)**: 키워드를 못 고르겠으면 **「기획 요청사항」 칸에 원하는 방향을 자유롭게** 적으면(예: "발레 입문자용 5편, 공연장 방문 팁·관람 매너 포함") 그대로 최우선 반영해 기획. `plan_series(..., request=...)` / `_series_prompt(..., request=...)`.
- **블로그의 색깔(정체성)** 안에서만 기획됩니다(예: 전통예술·공예 중심, 뻔한 관광지 회피).
- **시리즈 기획 단계 사진 폴더 지정(2026-07-03, 하위 폴더 편별 자동 매칭까지 확장)**: 실제 촬영한 사진이 있는데 시리즈가 사진과 무관한 소재로 기획되는 문제를 기획 단계에서부터 막기 위해, **「사진 폴더(선택)」** 입력칸을 추가(찾기/📚 내 사진에서 찾기/해제 버튼).
  - **상위 폴더 하나만 지정해도 하위 폴더를 자동 인식**: 시리즈는 보통 상위 폴더 하나 아래에 장소·소재별 하위 폴더가 나뉘어 있는 구조라, `_series_photo_folders(photo_dir)`가 바로 아래에 사진이 있는 하위 폴더들을 찾아줌(`photo_library.list_subdirs`). 하위 폴더가 **2개 이상이면** `plan_series()`가 폴더별로 각각 `_describe_photos()`(최대 2장)를 분석해 `[폴더 '이름']` 단위 블록으로 나눠 `_series_prompt`에 전달 — "각 편이 그중 하나씩을 중심으로 다루도록" 지시, 편별 소재가 실제 사진 폴더 구성과 어긋나지 않게 함. 하위 폴더가 없으면(사진이 바로 그 폴더 안에 있음) 기존처럼 전체를 한 번에 분석.
  - **[② 캘린더에 넣기]에서 편마다 서로 다른 하위 폴더를 배정 — 이름 기반 매칭(2026-07-08 버그 수정)**: 처음 구현(2026-07-03)은 i번째 편에 i번째 하위 폴더를 **폴더명 가나다순으로 그냥 순서대로** 배정해서, 편 내용과 무관한 폴더가 붙는 심각한 불일치가 발생했음(실사례: 울산 시리즈 10편 중 9편이 뒤섞임 — '주전 몽돌해변' 편에 '울산대왕암' 폴더 사진이 들어가 발행됨). `apply_series_to_calendar`가 이제 `_best_matching_folder()`로 **편의 제목·키워드와 폴더 이름이 실제로 겹치는지**(공백 제거 후 최장 공통 부분 문자열 + SequenceMatcher 유사도)를 계산해 가장 잘 맞는 폴더를 편마다 배정(한 폴더는 한 편에만). 맞는 폴더를 못 찾은 편은 폴더 미지정(라이브러리 자동매칭 폴백, 로그로 안내). **이미 발행된 글의 소급 교정**: `find_series_photo_mismatches(sid, data)`로 시리즈 전체의 현재 배정 vs 콘텐츠 기반 재계산을 비교(미리보기, 변경 없음) → `apply_series_photo_fixes(fixes, ...)`로 선택 적용 — 발행된 편은 `add_photos_to_published`(삭제·재발행 없이 같은 URL patch, 제목·본문·발행일 유지, 사진과 캡션만 교체), 미발행 편은 photo_dir만 변경. 이때 `apply_photo_folder(..., settings=)`에 settings를 넘기면 **교체된 사진에 맞는 캡션(alt)도 새로 생성**(`_fill_anchor_captions` — 예전엔 자리표시자만 다시 깔고 alt는 빈 채로 남아 다른 사진의 설명이 남는 문제가 함께 있었음).
  - **「📚 내 사진에서 찾기」 버튼**: 폴더 경로를 몰라도 라이브러리에서 바로 고를 수 있게, 팝업에 (1) 검색 탭 — `photo_library.search()`로 태그·장소·폴더명 매칭 후 결과를 폴더별로 묶어 매칭 사진 수와 함께 보여줌, (2) 폴더 트리 탭 — `photo_library.folder_tree()`로 이미 등록(스캔)된 사진들의 폴더 구조 전체를 트리로 보여줌. 더블클릭 또는 [✅ 이 폴더 사용]으로 즉시 사진 폴더 칸에 채워짐.
- **평소 주제(anchor_topics) 강제 연결 완화(2026-07-03, 버그 수정)**: 사용자가 구체적 요청(예: "울산 여행지 보고 느낀것들")을 했는데도, `_active_weekly_topics()`가 모아준 **7개 요일 주제 전부**(무용·민화·무대기술 등 무관한 것 포함)가 "연관시킬 것"이라는 강제 문구로 프롬프트에 들어가서, 실제로는 무관한 소재(예: 민화)가 시리즈에 억지로 섞이는 문제가 있었음. `_series_prompt`에서 **`request`가 있을 때는 anchor_topics를 "참고만 하고 안 맞으면 절대 끌어오지 말 것"으로 격하**, 규칙에도 "요청과 무관한 다른 소재를 억지로 갖다 붙이지 말라"를 명시. `request`가 없을 때(카테고리 선택 방식)는 기존처럼 평소 주제와 연관지어 기획.
- **사진 실제 내용을 글쓰기에 반영(2026-07-03, 근본 원인 수정)**: 그동안 `photo_vision.py`(Qwen2.5-VL로 사진을 실제 분석)의 결과가 **사진 라이브러리 태깅에만 쓰이고 본문 생성 프롬프트엔 전혀 안 들어가서**, 실제 사진(예: 울산 주전항 풍경)과 전혀 무관한 내용(민화 등)으로 글이 써지는 근본 원인이었음. `generate_post()`가 사진 확보 직후 새 함수 `_describe_photos()`를 호출 — 라이브러리에 이미 vision 태깅된 사진이면 그 캡션(`auto_caption`)을 재사용(빠름), 없으면 `photo_vision.caption()`으로 최대 6장까지 즉석 분석(로컬 vision 모델, 느릴 수 있음) — 그 결과를 "[실제로 준비된 사진에 담긴 내용 — 이것을 중심으로 소개하고, 없는 소재를 억지로 끌어오지 말 것]" 문구와 함께 `refs`에 자동으로 덧붙여 `_outline_prompt`/`_section_prompt`가 실제 사진 내용을 알고 글을 쓰게 함. 단어 사전 글(word_mode)은 사진 자체가 없는 개념 글이라 제외.
- **사진 그룹 기반 글 구성(2026-07-10, 사진↔글 정확 매칭)**: photo_dir이 지정된 사진 기반 글(예: 배재학당 여행)에서 "사진 내용과 글이 어긋나고, 중복·미사용 사진이 생기며, 사진이 하단 갤러리로 몰리던" 문제를 근본 해결. 원인은 ①`gen_captions`가 **파일명만** 보고 alt를 지어내고 ②`IMAGE_{i+1}`을 **섹션 순서 = 사진 순서**로 기계 매핑해 "1번 사진 ≠ 그 자리 글"이 됐던 것. 새 흐름(photo_dir 있을 때만, 일반 글은 기존 그대로):
  - **사진 개별 분석·그룹핑**(`_analyze_and_group_photos`): 폴더 전체 사진을 `photo_vision.caption()`으로 **한 장씩** 파악하고(완전중복은 파일 해시로 제거), 파일명+캡션을 LLM에 주어 '같은 대상'끼리 그룹으로 묶음(배재학당 11장 → 건물 전경/아펜젤러/이승만 3그룹). 전경·외관 성격(`is_overview`) 그룹을 맨 앞으로.
  - **섹션 교차 배치**(`_photo_based_sections`): sections를 `[사진 그룹, 트렌드, 사진 그룹, 트렌드, …]`로 조립 — **사진 섹션으로 시작·끝, 사진↔트렌드 번갈아**(사진 그룹 N개 → 트렌드 N-1개). 첫 화면에 대표 전경이 와서 딱딱하지 않게. 트렌드 섹션은 `keyword_pool`의 대기 키워드를 씨앗으로(소진 안 함) LLM이 "요즘 관심사 × 이 장소"로 연결(`_trend_sections`).
  - **사진↔섹션 정확 배치**(`_generate_multi(..., photo_groups=)`): 각 사진 섹션 소제목 뒤에 **그 그룹 사진들**을 배치하고, 본문도 그 그룹의 vision 캡션(intent)을 근거로 작성돼 사진과 글이 일치. 사진은 '그룹 순서'로 전역 IMAGE 번호(1..M)를 매기고, `generate_post`가 그 순서(`cfg["photo_order"]`)를 저장 → `publish_date`가 발행 때 같은 순서로 업로드해 자리표시자와 사진이 정확히 매칭. 갤러리 몰림 제거, 그룹당 최대 5장(사진첩화 방지), 중복 제거.
  - **사진 설명(캡션)은 파일명 + 비전을 결합한 자연스러운 문구**(2026-07-10 추가): 예전엔 사진 아래 캡션이 vision 자동캡션(부정확: 아펜젤러 동상→"금강산 조각상")이라 사진과 안 맞았음. `_describe_captions`가 **파일명(운영자가 적은 정확한 제목, 순번 숫자 제거)을 앵커로 하고 비전 분석을 참고**해 "웅장하게 서 있는 아펜젤러목사 동상", "기념비적인 모습의 이승만 박사의 동상"처럼 딱딱하지 않고 설명적인 캡션을 LLM으로 생성(비전이 파일명과 어긋나면 파일명 우선). → **사진 파일명에 대상을 적어두면 그게 캡션의 뼈대가 됨**. 실패 시 파일명 정리(`_caption_from_filename`)로 폴백. 영어 alt는 그룹 제목(label_en).
  - **그룹 안 사진은 전경→부분 순서**(2026-07-10): `_group_photos_prompt`가 각 그룹의 `photo_numbers`를 **전체를 넓게 보여주는 전경·전체 사진을 먼저, 부분·근접(클로즈업)·세부 사진을 나중에** 오도록 정렬 지시 — "전체를 보여주고 그 부분을 보여주는" 자연스러운 흐름.
  - **설명판·비석 사진은 본문에서 빼고 글자만 판독(OCR)해 내용에 반영**(2026-07-10): 설명판·안내문·비석 사진은 글자만 있어 밋밋하므로 **본문에 넣지 않고**, `photo_vision.ocr()`(qwen2.5vl, 1600px)로 그 글자를 판독해 "[사진 속 설명판에 적힌 내용 — 본문에 정확히 녹여 서술]"로 refs에 넣어 본문의 역사·설명 정확도를 높인다(`_ocr_signboards`). 판별: 파일명에 **설명·안내·비석·비문·현판·표지·기념비·설명문** 등이 들어간 사진(`_SIGN_KEYWORDS`). 실측: 아펜젤러 목사 설명판 → "1858년 펜실베니아 출생… 1885년 부활절 인천 입국… 정동에 배재학당 설립… 1902년 군산 앞바다 순교"까지 문장 단위로 판독됨.
  - **사진은 본문 문단 사이에 분산 + 섹션 제목 격상**(2026-07-10): (1) 사진 섹션에서 전경(첫 사진)은 소제목 바로 뒤에, 나머지 사진은 `_insert_midbody_figures`로 본문 문단(`</p>`) 사이에 균등 분산 — "사진 5~6장 줄줄이 → 글" 대신 "문단 → 사진 → 문단 → 사진"으로 글과 함께 보이게. (2) `_group_photos_prompt`가 그룹 제목(label)을 단순 분류명("인물 흉상")이 아니라 **의미·역할을 살린 격조 있는 소제목**으로 짓게 지시(예: 교회 창시 목사 흉상 → "이 땅에 복음을 심은 선구자들", 건물 전경 → "붉은 벽돌에 새겨진 신앙의 유산").
  - 배재학당·정동제일교회 글은 이 방식으로 재생성해 **같은 URL 유지(posts().patch, slug·발행연월 불변)**로 재발행(사진↔섹션↔글 일치, 설명적 캡션·격상 제목·문단 분산 확인).

  **▶ 운영 가이드 — 사진 찍고 파일명 적는 법(이 기능을 잘 쓰려면)**:
  1. **파일명에 무엇을 찍었는지 적기** — 예: `명동성당 종탑.jpg`, `제단 스테인드글라스.jpg`. 이 파일명이 사진 설명(캡션)과 본문 소재의 뼈대가 됨(vision보다 파일명을 우선 신뢰).
  2. **같은 대상은 이름을 비슷하게** — 예: `대왕암 전경1.jpg`, `대왕암 바위2.jpg`처럼 같은 대상이면 한 그룹(한 소주제)으로 묶임. 끝의 순번 숫자(1,2…)는 캡션에서 자동으로 떼어짐.
  3. **전경 → 부분 순서로 담기** — 전체가 보이는 전경 사진과 부분·클로즈업을 모두 찍으면, 전경이 먼저 배치됨(파일명에 '전경/외관/전체'를 넣으면 더 확실).
  4. **설명판·안내문·비석 사진은 파일명에 '설명문/안내/비석' 등을 넣기** — 그러면 그 사진은 **본문에 안 들어가고**, 대신 거기 적힌 글자를 읽어 본문 내용에 정확한 정보로 반영됨(예: `아펜젤러 목사 설명문.jpg`).
  5. 사진 폴더는 [🗓 날짜별 발행]에서 그 날짜에 지정(하위 폴더가 있으면 자동 인식). 사진 없이 발행하면 자동 이미지 검색으로 채워지므로, **사진 기반 글은 발행 전 폴더 지정 필수**.
- **[■ 기획 중단]**(2026-07-03): 편수를 잘못 입력하는 등 실수를 깨달았을 때 기획 진행 중에도 눌러서 멈출 수 있음(그동안은 완료·실패까지 무조건 기다려야 했음). `plan_series(..., stop_check=...)`가 재시도 루프 진입 직전마다 중단 여부를 확인 — **단, 이미 보낸 LLM 요청 1회는 응답이 올 때까지 그대로 기다림**(진행 중인 네트워크 호출 자체를 강제로 끊지는 않음), 그 다음 재시도부터 멈춤. 중단하면 버튼이 곧바로 다시 활성화돼 편수를 고쳐 재시작 가능.
- **캘린더 배정 시 건너뛴 날짜 안내(2026-07-03, 버그 아님으로 확인됨)**: "② 캘린더에 넣기"로 시리즈를 배정할 때, 이미 발행된 날짜와 겹치면 조용히 건너뛰고 있었음(안전장치 자체는 정상 — 발행된 글을 안 덮어씀). 다만 **로그에 알려주지 않아서** "10편 기획했는데 1편만 들어갔다"처럼 오해를 낳는 경우가 있었음(그 기간에 요일별 자동발행으로 이미 대부분 채워져 있었던 것). `apply_series_to_calendar(..., log=...)`가 이제 건너뛴 날짜 개수·목록을 로그와 완료 팝업에 명시. 배정된 편이 0개면(전부 겹침) 예외 없이 안내 메시지로 처리(과거엔 `assigned[0]` 참조로 조용히 죽을 수 있었음).
- **시작일이 과거면 확인 질문(2026-07-03)**: 자동 발행이 켜진 상태에서 과거 날짜로 시리즈를 배정하면 배정 직후 그 날짜가 바로 자동발행 대상이 되어 버릴 수 있음 — 시작일이 오늘 이전이면 배정 전에 경고 문구가 포함된 확인 질문을 한 번 더 띄움.
- **🛑 지금 작업 중단(2026-07-03, 전역 기능)**: 그동안 자동발행·수동 생성/발행 중엔 **중단할 방법이 전혀 없어서** 잘못된 입력으로 시작된 글 생성·발행을 끝까지 지켜볼 수밖에 없었던 문제 해결. 화면 하단 진행률 바 옆에 **[🛑 지금 작업 중단]** 버튼(항상 표시, `stop_current_job`) 추가 — 누르면 `self.stop_requested`+`_batch_stop`+`_plan_series_stop`을 한번에 세팅해 수동 생성/발행·자동발행·묶음발행·시리즈기획 전부에 동시 적용됨.
  - `generate_post`/`_generate_multi`가 **개요 재시도 직전 + 소주제 작성 시작 직전마다** `stop_check()`를 확인해 중단(전용 예외 `StopRequested` — `RuntimeError` 상속이라 기존 처리와도 호환되지만, "다단계 생성 실패 시 단일 생성으로 폴백" 로직이 사용자 중단을 일반 실패로 오인해 재시도하지 않도록 `except StopRequested: raise`로 먼저 걸러냄).
  - `publish_date`는 **사진 업로드 직전 + (재발행 삭제 시작 직전)** 두 곳에서만 확인 — **"기존 글 삭제→새 글 발행" 구간은 원자적 단위로 취급해 그 사이엔 절대 체크 안 함**(중간에 멈추면 옛 글은 지워지고 새 글은 안 올라간 상태가 될 위험이 있어서).
  - 진행 중인 LLM 응답 1회나 위 원자적 구간은 끝까지 기다린 뒤 멈추므로, 버튼을 눌러도 완전히 멈추기까지 몇 초~수십 초 걸릴 수 있음(즉시 강제 종료가 아니라 "다음 안전한 지점에서 중단").

### 🤖 AI 글 작성 (gemma4 / Claude)

### ✅ 사실 검증 / 할루시네이션 방지 (`factcheck.py`)
- LLM이 지역 정보(대표 메뉴·맛집 등)를 **지어내는 문제** 방지. 2단계:
  - **C. 무근거 단정 금지(`FACT_RULE`, 항상 적용)**: '지역 대표 메뉴·시그니처·특정 상호·가격·운영시간'을 근거 없이 단정 금지 → 안전한 일반화로. 개요·소주제·실용정보/FAQ 프롬프트에 모두 포함(키 불필요).
  - **A. 네이버 그라운딩(키 있을 때)**: 개요(장소 파악) 후 **네이버 지역검색 + 백과사전 + 뉴스**로 실제 정보를 받아 `[검증된 현지 정보]/[백과사전 사실]/[최근 뉴스]`로 프롬프트에 주입 → 사실 위에서 작성. `factcheck.grounding_facts(topic, location, settings)`.
    - **지역검색**(음식점·주변)은 *실제 장소(location)일 때만* — 비장소 주제(예: 승무)는 자동 생략해 노이즈 방지. **백과사전**(정의·연대·유래)은 항상. **뉴스**는 참고용 1~2건.
    - 예: 백운호수 백과사전이 "한식마을"이라고 알려줘 '매운탕 대표메뉴' 오류를 원천 차단.
- 키 발급: [developers.naver.com](https://developers.naver.com) → 애플리케이션 등록 → 검색 API → client_id/secret → [⚙️ 설정]의 **네이버 ID / 네이버 Secret**(무료). 키 없으면 A는 생략하고 C만 적용.
- 실증: '의왕 백운호수 대표 메뉴=매운탕'은 네이버 실제 결과(한정식·곤드레·돈가스·백숙 위주, 매운탕 1곳)와 불일치 → 할루시네이션 확인됨.

### 📚 내 사진 라이브러리 (`photo_library.py`, 1A 완료)

- **폴더 트리 탐색기(스캔 안 한 폴더도 미리보기)**: [📚 내 사진] 좌측에 **실제 컴퓨터 폴더 구조**를 탐색기처럼 보여줌(`photolib.list_subdirs`로 클릭해서 펼칠 때만 디스크 조회, 느려지지 않게). 등록(스캔)된 폴더는 **✅** 표시 + 사진 수, 등록 안 된 폴더도 디스크 기준 사진 수가 그대로 보임. 폴더 클릭 → 그 폴더(+하위) 사진이 **등록 여부와 무관하게** 목록에 표시(`list_image_files`+`photos_by_paths`로 디스크·DB 병합) → 미등록 사진도 바로 보고 태그를 달면 그 자리에서 즉석 등록(`register_file`).
  - **트리 폭 조절+스크롤**: 폴더트리|사진목록|상세 3칸을 `ttk.PanedWindow`로 묶어 경계선을 끌어 폭 조절 가능. 트리에 가로 스크롤바 추가(`ftv.column("#0", width=900, stretch=False)`)로 하위 폴더로 갈수록 깊어지는 들여쓰기 때문에 폴더명이 안 보이던 문제 해결. (주의: PanedWindow 안 패널에 `width=`만 주면 자식 위젯 요청 크기에 맞춰 자동으로 커져 다른 칸을 밀어내므로 `grid_propagate(False)` 필수. 초기 분할 비율은 탭이 실제로 화면에 보이는 `<Map>` 이벤트에서 1회만 `sashpos`로 지정 — 너무 일찍(탭이 안보일 때) 호출하면 폭이 0으로 깨짐.)
- **선택한 사진 여러 장 일괄 태그**: 사진 목록 다중 선택(Ctrl/Shift) 후 **[🏷️ 태그 추가]**(입력한 태그를 선택 전체에 병합) / **[🗑️ 태그 지우기]**(선택 전체 태그 비우기). `photolib.merge_tags()`(공용 헬퍼, photo_vision도 같이 사용)로 기존 태그 보존+중복 제거.

  - **핵심 원인**: `tk.Label`에 글자색을 따로 안 주면 Windows 기본값이 `'SystemButtonText'`인데, 인식 목록엔 `'systemwindowtext'`만 있어 매칭 실패 → **fg를 안 정한 거의 모든 라벨이 다크 배경에서 영원히 검은 글자로 남음**(시리즈/주간/날짜별 탭 등 전체에 광범위 영향). `_DEFAULT_FG`에 `"systembuttontext"` 추가로 해결.
  - **비활성 버튼 회색 글자 안 보임**: 비활성(`disabled`) 버튼 글자색이 배경색 밝기와 무관하게 고정 회색(`#777777`/`#8a8a8a`)이라, 중간 밝기의 색깔 버튼(녹색·파랑 등)에서 명도가 비슷해 거의 안 보였음 → `_disabled_fg_for(bg)`가 **그 버튼의 실제 배경색 기준으로 흰/검정 쪽으로 섞은 톤**을 계산(`_blend_hex`)해 어떤 배경 색이든 항상 충분한 대비 확보.
  - **Spinbox·일반 Scrollbar 테마 누락**: `_theme_one`에 `Spinbox`/`Scrollbar`(scrolledtext 내부) 분기가 없어서 흰 배경+검은 글자 그대로 남아 다크 UI에서 튀어 보임(="흰 테두리·고대비" 체감) → 두 클래스 모두 테마 적용.
  - **팝업창 전체가 테마 미적용**: `tk.Toplevel`로 띄우는 10개 다이얼로그(로그인 관리·이벤트 추가·발행글 목록·이미지 찾기·블로그 추가 등)는 모두 시작 시 1회 테마 적용 *이후*에 생성돼 한 번도 다크 테마가 안 입혀짐 → 각 팝업에 `win.bind("<Map>", ...)`을 달아 **화면에 그려지는 순간 자동으로 테마 적용**.
  - **정보용 파란 글자 저대비**: `#1565c0`/`#0277bd`(라이트 모드 전제로 고른 진한 남색)가 다크 패널 위에서 대비가 약함 → `_INFO_FG` 인식 추가로 테마의 강조색(`accent`)으로 자동 치환. 동적으로 색을 다시 칠하는 2곳(`origin_lbl`/`status_lbl`)도 고정값 대신 `self._theme["accent"]` 참조로 변경.
  - 검증: 위젯 전수 스캔(bg/fg 명도차 자동 계산) 기준 저대비 위젯 0개, 실제 다크모드 스크린샷으로 시리즈/주간/날짜별(주간·일간)/팝업 모두 확인.

### ⚠️ 사진 자동탐색 (기본 꺼짐)
- 예전엔 폴더 미지정 시 `C:\blogger\YYYY\MM\YYYYMMDD`(완료된 `--` 폴더 포함)를 **날짜로 자동 탐색**해 사진을 넣었는데, 시리즈 글 등에 **무관한 옛 사진이 끼어드는 문제**가 있었음.
- **이제 기본값은 '직접 지정한 폴더의 사진만' 사용**(설정 `auto_date_photos=False`). 날짜 자동탐색을 원하면 그 값을 True로.
- `resolve_photos(date, photo_dir, allow_auto)` / `generate_post`·`publish_date`가 설정값을 전달.

### ⏱ 발행 시각 차등
- 한국어 글을 영문보다 **랜덤 1~2시간 이른 시각**으로 발행 표시(매번 다르게).
- **발행 표시 날짜 = 예약된 날짜**: 과거 날짜로 예약한 글을 (밀려서) 나중에 발행해도 **그 예약 날짜로 표시**됩니다(오늘로 안 찍힘). 미래로 예약된 걸 수동 발행하면 '지금'으로. `publish_pair(..., base_dt=planned_datetime)`.

### 🌐 멀티 블로그 (다른 계정 포함)
- 블로그마다 정체성·키워드·캘린더·주간·시리즈가 **독립 저장**.
- 헤더 드롭다운으로 전환, **[+ 블로그 추가]** 로 새 블로그 등록.
- 프로그램을 켜 두면 **등록된 모든 블로그가 각자 캘린더대로 자동 발행**.

### ⏰ 자동 발행
- 설정에서 발행시각 + 자동발행 체크 → **프로그램만 켜 두면** 그 시각에 자동 발행.
- 꺼져 있던 동안 지난 발행 건은 다시 켜면 자동으로 올라감.

- **반입 폴더·정리 폴더 기본값**(`photo_intake.py`): 윈도우는 기존 `D:\Source\한국사진\...` 유지, 맥은 `~/한국사진/...`. `settings`에서 언제든 원하는 경로로 지정 가능.
- **그대로 되는 것**: Tkinter GUI, Ollama, Playwright(Chrome 채널 자동 인식), Blogger OAuth — 수정 없이 크로스플랫폼.
- **검증 상태**: 컴파일·GUI 셀프테스트(`--selftest`)는 윈도우에서 통과. **실제 맥 실기 테스트는 아직 안 함** — 폰트 인덱스·exiftool 인식·`.command` 실행권한을 맥에서 한 번 확인 필요.

## 5. 핵심 동작 원리 (참고)

- **글 생성**: gemma4(26B)는 한 번에 몰아 쓰면 빈약해서, **개요→소주제별→맺음말**로 여러 번 나눠 호출.
  소주제 본문이 짧으면 최대 3회 재시도, 그래도 짧으면 경고 로그.
- **이미지 업로드**: Blogger API엔 이미지 업로드가 없어 **Playwright 브라우저로 에디터를 조작**.
  새 에디터는 OS 파일창(`showOpenFilePicker`)을 써서, 그 함수를 **우리 파일을 반환하도록 바꿔치기** +
  "이미지 추가" 다이얼로그의 **"찾아보기"** 클릭으로 업로드. API 임시 초안 편집 페이지를 사용(권한 403 회피).
- **멀티 블로그**: 블로그별 폴더(`profiles/<id>/`)에 데이터·인증을 분리. 전환 시 경로를 통째로 스왑.

## 7. 그동안 해결한 주요 문제 (개발 이력 요약)

- 글이 짧고 빈약 → **소주제별 다단계 생성**으로 풍부하게(한 4,000자/영 8,000자급)
- 소주제 도입부가 다 비슷 → 각 섹션에 전체 구성 알려 **도입부 차별화**
- 흔한 관광 주제만 나옴 → **블로그 색깔(정체성) + 차별화 규칙**으로 전통예술·공예 중심
- 멀티 블로그(다른 계정) 지원 → **프로필/레지스트리 + 계정별 인증**
- 새 Blogger 에디터 이미지 업로드 실패(403 / 파일창 / 캐시 URL) → **임시 초안 + showOpenFilePicker 오버라이드 + 찾아보기 클릭 + DOM 기반 URL 추출**로 완전 해결
- **업로드 후 로고가 사진 자리에 나옴(2026-07-09, 버그 수정)**: 업로드 완료 URL을 before/after 차집합으로만 판단해서, 페이지에 이미 떠 있던 Blogger 기본 로고 이미지(PNG 58KB)가 '새 URL'로 오탐되어 실사진 대신 통째로 삽입되던 사고. `_upload_one`이 이제 후보 URL을 **실제로 다운로드해 Content-Type=jpeg + 용량이 업로드 파일의 50%↑인지 검증**(`_verify_uploaded_url`)해 통과한 것만 채택(로고 같은 무관 이미지는 절대 안 들어감). 이미 오염된 울산 시리즈 20개 글은 소급 재교정 완료.
- **'(임시) 이미지 업로드' 초안이 초안함에 쌓임(2026-07-09, 버그 수정)**: 사진 업로드는 API 임시 초안(`_create_temp_draft`)을 만들어 그 편집 페이지에서 수행하고 끝나면 삭제하는데, 업로드 중 프로세스가 중단/크래시되거나 삭제 API가 실패하면 임시 초안이 남았음(사용자 신고 시점 10개 잔류 — 초안이라 공개엔 안 보이나 관리 화면엔 노출). 이제 새 임시 초안을 만들기 **직전에** `_cleanup_stale_temp_drafts`가 제목이 정확히 `(임시) 이미지 업로드`인 초안을 모두 먼저 삭제해 누적을 원천 차단(고정 제목 완전일치만 지워 실제 글은 안 건드림).
- 슬러그가 잘려 죽은 URL/색인 오류 → **슬러그 길이 제한 + 잘림 허용**
- 사진 크기 들쭉날쭉 → **/s1600/ 통일 + 폭 100%**
- 단독 글에 가짜 "다음 편" 예고 → **시리즈일 때만 예고**
- 한·영 발행 시각 → **한국어를 1~2시간 랜덤 이르게**
